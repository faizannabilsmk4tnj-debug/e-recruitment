### Grup 1 — Manajemen Pengguna

**`users`** adalah tabel inti untuk semua akun. Kolom `role` berisi enum `hr` atau `applicant`, sehingga satu tabel cukup untuk kedua aktor. Password disimpan sebagai `password_hash` (bcrypt) — tidak pernah plain text. Kolom `is_active` untuk suspend akun tanpa hapus data.

**`user_profiles`** dipisah dari `users` agar tabel utama tetap ramping dan query autentikasi cepat. Berisi data personal seperti bio, alamat, tanggal lahir, dan link LinkedIn/portfolio.

### Tambahan pada tabel `job_postings`

Di MySQL, full-text search didukung natively dengan `FULLTEXT INDEX`. Kolom yang perlu diindeks adalah `title`, `description`, `requirements`, dan `benefits` — karena itulah kolom yang paling relevan saat kandidat mengetik keyword seperti "software engineer", "remote", atau "minimal S1".

Tidak perlu tabel baru. Cukup tambahkan **FULLTEXT index** pada tabel `job_postings` yang sudah ada:

```sql
ALTER TABLE job_postings 
ADD FULLTEXT INDEX ft_job_search (title, description, requirements, benefits);
```

Lalu di Laravel, query-nya menggunakan `MATCH ... AGAINST`:

```php
$results = JobPosting::whereRaw(
    "MATCH(title, description, requirements, benefits) AGAINST(? IN BOOLEAN MODE)",
    [$keyword]
)->where('status', 'open')->get();
```

---

### Tambahan tabel `saved_jobs` (bookmark lowongan)

Sekaligus saya tambahkan tabel bookmark yang tadi saya sebut, karena keduanya sering berjalan bersama di platform rekrutmen seperti Jobstreet:

```sql
CREATE TABLE saved_jobs (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id     BIGINT NOT NULL,
    job_id      BIGINT NOT NULL,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uq_saved (user_id, job_id),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (job_id)  REFERENCES job_postings(id) ON DELETE CASCADE
);
```

Tabel ini sangat ringan — hanya 4 kolom. `UNIQUE KEY` pada `(user_id, job_id)` memastikan satu pelamar tidak bisa menyimpan lowongan yang sama dua kali.

---

### Tambahan tabel `job_search_logs` (opsional tapi sangat berguna)

Ini tabel opsional untuk mencatat riwayat pencarian pelamar. Berguna untuk fitur "pencarian terakhir" dan bisa dipakai HR untuk melihat keyword apa yang paling banyak dicari:

```sql
CREATE TABLE job_search_logs (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id     BIGINT NULL,
    keyword     VARCHAR(255) NOT NULL,
    results_count INT DEFAULT 0,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL
);
```

`user_id` boleh `NULL` karena pencarian bisa dilakukan tanpa login.
